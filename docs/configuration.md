# Configuration

There are two layers:

1. **Module options** — build-time configuration in `nuxt.config.ts` under `comments`.
2. **Runtime configuration** — generated by the module into Nuxt's `runtimeConfig`, overridable at runtime with environment variables.

Secrets and authentication configuration do **not** belong to this module; they belong to Better Auth (see [authentication.md](./authentication.md)).

## Module options

```ts
export default defineNuxtConfig({
  comments: {
    database: {
      binding: 'DB',
    },
    pagination: {
      pageSize: 20,
      maxPageSize: 100,
    },
    reactions: {
      enabled: true,
      types: ['like', 'heart', 'laugh'],
    },
    limits: {
      maxBodyLength: 4000,
      maxResourceLength: 512,
    },
    components: {
      prefix: 'Nuxt',
    },
    rateLimiter: 'memory',
    rateLimiterTrustProxy: false,
  },
})
```

| Option | Type | Default | Description |
|---|---|---|---|
| `database.binding` | `string` | `'DB'` | Name of the D1 binding to read from `event.context.cloudflare.env`. Must match your Wrangler file. |
| `pagination.pageSize` | `number` | `20` | Default page size for list endpoints and the client composable. |
| `pagination.maxPageSize` | `number` | `100` | Hard cap on `?limit=` values. Requests above this are clamped, never rejected. |
| `reactions.enabled` | `boolean` | `true` | Turns the reaction endpoints and UI data on/off. |
| `reactions.types` | `string[]` | `['like']` | Allowed reaction type strings. Validated server-side; rendered only when you provide a `#reaction` slot or custom UI. |
| `limits.maxBodyLength` | `number` | `4000` | Maximum comment body length in characters. |
| `limits.maxResourceLength` | `number` | `512` | Maximum normalized resource identifier length. |
| `components.prefix` | `string` | `'Nuxt'` | Component name prefix. Set to `''` for `<Comments>`, `<Comment>`, …. |
| `rateLimiter` | `'none' \| 'memory'` | `'memory'` | Mutation rate limiting. `'memory'` is a per-isolate in-memory limiter (single-isolate only). |
| `rateLimiterTrustProxy` | `boolean` | `false` | Trust `x-forwarded-for` for rate-limit identity. Enable only behind a trusted proxy; otherwise `cf-connecting-ip` is used. |

### Component naming

The default prefix means the public components are:

```text
<NuxtComments> <NuxtComment> <NuxtCommentComposer> <NuxtCommentReactions> <NuxtCommentAuth>
```

Set `components.prefix: ''` to use the unprefixed names:

```text
<Comments> <Comment> <CommentComposer> <CommentReactions> <CommentAuth>
```

Both forms are the same components. The module registers them explicitly with `addComponent`, so they work from `node_modules` without relying on local auto-import scanning.

## Runtime configuration

### Server-only (`runtimeConfig.comments`)

| Key | Description |
|---|---|
| `databaseBinding` | Resolved from `database.binding`. |
| `rateLimiter` | Resolved from `rateLimiter`. |

### Public (`runtimeConfig.public.comments`)

| Key | Description |
|---|---|
| `pagination` | `{ pageSize, maxPageSize }` |
| `reactions` | `{ enabled, types }` |
| `limits` | `{ maxBodyLength, maxResourceLength }` |
| `componentsPrefix` | The resolved component prefix (informational). |

No secrets are ever written to the public runtime config. The components read `runtimeConfig.public.comments` for reaction types and pagination defaults.

### Environment variable overrides

Nuxt maps runtime config to environment variables with the `NUXT_` prefix. For example:

```bash
NUXT_COMMENTS_DATABASE_BINDING=COMMENTS_DB
# public config (client-visible — never put secrets here):
NUXT_PUBLIC_COMMENTS_PAGINATION_PAGE_SIZE=50
```

Because `reactions.types` is an array, configure it through the module option rather than an environment variable.

## Resource identifiers

A resource is an opaque, non-empty string identifying what a thread belongs to — usually a blog post path, but it does not have to be a URL.

```vue
<Comments resource="/blog/memorylessness" />
<Comments resource="blog:memorylessness" />
```

**Normalization contract.** Before storage and querying, a resource is normalized deterministically:

- surrounding whitespace is trimmed;
- leading slashes are stripped (`/blog/x` and `blog/x` are the same resource);
- repeated slashes are collapsed (`/blog//x` → `blog/x`);
- a trailing slash is removed;
- case is preserved;
- the result must be 1–512 characters;
- the reserved prefix `threads/` is rejected (it is used by comment-scoped API routes, see [api.md](./api.md)).

Store the resource you render the component with; `normalizeResource` is applied consistently on the server and when building API paths on the client. Because the canonical form never has a leading slash, the identifier round-trips through `/api/_comments/:resource` without ambiguity.

## Limits and validation

All server inputs are validated with shared [Valibot](https://valibot.dev) schemas in `src/runtime/shared/schemas.ts`:

- resource identifiers: non-empty, ≤ `maxResourceLength`, not the reserved prefix;
- comment bodies: non-empty, ≤ `maxBodyLength`;
- reaction types: must be in `reactions.types`;
- pagination `limit`: integer, clamped to `[1, maxPageSize]`;
- parent comments: must exist, must live on the same resource, must not be deleted.

See [api.md](./api.md) for the HTTP status mapping.
